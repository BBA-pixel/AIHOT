## 功能验证

- 管理员认证、CSRF、整数范围 1–32、必填修改原因及未知字段拒绝均通过。
- 未保存时使用代码默认值；保存后重新加载能读到数据库中的值，不读取并发环境变量。并发保存的审计前后值连续，审计事务失败会同时撤销配置修改。

- 事件归组保持串行；配置只调整四类任务的单 worker 并发，不是所有模型 HTTP 请求的全局总并发。

## 全量回归限制

当前 Windows 环境为 Node.js 24.16.0、临时 PostgreSQL 18：

- 首次后端全量运行的既有 `analyze-shutdown` 测试等待 `SIGTERM` 回调超时；Windows 不能提供该用例要求的 POSIX 进程信号语义，已终止这次超时运行。
- 将 `analyze-shutdown`、`translate-shutdown`、`backup` 三个 POSIX/工具依赖文件留给 Linux 后，Windows 回归为 912 项、908 通过、4 失败。其中两项是 `response-header-limits` 子进程退出时的 libuv 原生断言 `UV_HANDLE_CLOSING`；另两项为缺少 OpenSSL 和测试进程 ID 重用造成的测试库名称冲突。复用本机 OpenSSL、使用新测试库单独复核后，TLS 5 项与搜索共享 4 项均通过，libuv 原生退出错误仍待 Linux 复核。
- 网页全量首次 60 项、57 通过、3 个既有 WebKit 阅读交互用例失败；单独复核后目录键盘滚动通过，搜索建议重开与长列表返回位置两项仍未通过。新后台表单在两种浏览器中均通过。
- 尝试启动已有 Docker Desktop 以补充 Linux 回归，但其启动被自身 `dockerInference` IPC 文件错误阻断，未能完成 Linux 全量检查。

因此不能把这次验证描述为“全量测试全部通过”。上述回归失败未通过更改测试断言、公共阅读逻辑或付费调用逻辑来规避。提交上游前，应在可用的 Linux/Docker 环境补齐完整 CI。
