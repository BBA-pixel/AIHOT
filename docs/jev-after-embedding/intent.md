### I1. 目标与非目标

在**普通报道的 Embedding 候选召回之后、现有归组判定之前**增加 Jev，识别“语义相近，但不是同一事件”的候选。

**第一版只新增一道关系否决门，不替换现有归组模型，不重构流水线。** Jev 判断为 `UNRELATED` 的候选，不得经本次模型归组路径被合并或作为故事连接依据；其他结果继续由原流程决定。Jev 的肯定判断不直接写事件归属。

理由：现有 `judgeBatch()` 同时判断事件关系和 `selection.addsValue`（相对已公开精选是否有新增价值）。直接把它替换成 Jev，或删掉候选后再调用它，会改变精选去重语义，超出“最简添加”的范围。

不做：

- 不增加任务队列、数据库表/列、公开 API、前端页面或新的模型路由框架。
- 不替换 Embedding，不重建向量索引，不改变向量模型和文本格式。
- 不修改召回窗口、数量、相似度门槛：现有普通报道为最近 14 天、`RECALL_TOP_FACTS = 10`、`RECALL_MIN_COSINE = 0.6`。**本次不顺带改成 Top20/30。**
- 不替换合并复核、精选增量判断、故事整合、人工纠正和写入事务。
- 不扩展到 signal 帖子分支；不对已有人工归属、保留原归属的修订、同 URL 确定归属、已识别综合稿增加 Jev 门控。
- 不自动重跑历史数据。

### I2. 业务成功标准与假设

- 目标是减少“语义相近但不同事件”的自动关联，不把“新增一个模型调用”本身当成收益。
- 保留原归组与精选职责；这版是新增否决门，**不是用 Jev 替换原模型**。这是本方案的设计选择，需在 G0 确认，而不是声称用户已明确批准该算法。
- 可接受的事实/故事召回下降、误拆分增加、单篇成本和时延上限，由用户/维护者在上线前确认。未确认前不开生产开关，不能以零负例误接受代替业务验收。
- 依赖现有 Embedding、有效 OpenRouter 凭证及预算能力；不假设新服务天然已有预算行。

### I3. 现有证据及不足

- 本地 v3：180 个负例判定（101 篇不同负例报道）误接受 0；9 个正例对照通过；6 个边界案例未计分。标签是助手初标，不是独立人工金标；高于现有 0.6 相似度门槛的负例只有 11 对。
- v2 近似增量实验仍有误合并和故事碎裂。**因此“测试没问题”只表示目前没有发现该明确负例集上的误接受，不表示生产接入已验收。**
- 本文的“Jev 否决 + 原归组”组合尚未进行完整端到端实测；第一版默认关闭正是为了保留验收边界，不宣称必然提升整体 P/R。
- 原始实验在 `.data/jev-eval/negatives-v3/` 与 `.data/jev-eval/stream-v2/`，不提交密钥或原始实验目录；报告与样本清单已在会话交付。
- 当前代码依据：`events/group.ts`、`events/relate.ts`、`providers/embeddings.ts`、`providers/receipts.ts`、`config.ts` 及 `docs/grouping.md`。
- Jev 协议依据：[OpenRouter 官方 Jev 接入说明](https://openrouter.ai/blog/tutorials/how-to-use-jev/)。Decisions API 的 choice 输出包含类别、概率及独立 confidence；不能将其当作 chat preset。
