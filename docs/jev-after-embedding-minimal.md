### V3. 评审重点与已知风险

- **误拒绝：**Jev 错判 UNRELATED 会造成漏并；保留原 LLM 不能救回已被否决的关系。需 AC10 检验，不能只看 precision。
- **成本与时延：**原 LLM 调用不减少；逐候选顺序调用增加开销。先测量，不在第一版加入并发调度系统。
- **精选行为：**完整输入必须保留；关系变化仍可能间接改变最终精选结果，因此既做逻辑回归，也看回放中的精选差异。
- **恢复与审计：**所有新增回执必须进入提交/恢复路径；原 batch receipt 的主回执含义不变，不能只保存最后一个 Jev 回执。
- **配置安全：**无预算行不是默认限额；缺配置必须明确报错。密钥、付费开关、测试环境不可混用。

## Handoff — 交给下一位如何继续

### H1. 开发交接

- 交付物：独立的 [Intent](jev-after-embedding/intent.md)、[Spec](jev-after-embedding/spec.md)、[Plan](jev-after-embedding/plan.md)，以及本入口中的 Review / Handoff。实施规则保持“最小添加”。
- 当前停点：实现与定向检查完成，提交 PR；后续完成必要发布检查与业务回放，不直接开启开关。
- 需求来源：用户要求 Embedding 后增加 Jev，明确配置/代码位置，最简化实现，并按 SDLC 写文档。
- 代码入口：[Spec 的 S3–S6](jev-after-embedding/spec.md)；验收依据：Spec 中 R01–R09 与本入口中 AC01–AC10；既有实验只作 Intent 中 I3 的背景证据。
- 待确认事项：真实回放的质量/成本/时延容忍度；生产请求预算与发布责任人。无须提供密钥到文档中。
- 后续交付必须附：实际改动文件、AC 测试证据、失败/跳过项与原因、回放报告、发布/关闭步骤。不得只报“测试没问题”。

### H2. 发布、运维与关闭（R08）

1. 交付代码和本地测试时保持 `GROUP_JEV_ENABLED=false`。
2. 管理员配置密钥及 `openrouter-jev` 预算；完成真实候选回放验收。
3. 明确启用后再设 `GROUP_JEV_ENABLED=true`，重启相应 worker；读者请求仍不触发模型。
4. 临时关闭时设回 false 并重启 worker，后续任务恢复原流程。关闭不自动回滚已写入的归组；需要纠正的内容走现有人工纠正/重归组入口，不批量删除历史。

临时关闭不等于移除功能。若最终放弃接入，应同一次改动清理新增代码、配置项、测试、文档和专用预算配置，遵守项目现有移除约定。

### H3. 完成定义

- **本轮文档完成：**Intent、Spec、Plan、Review、Handoff 齐全；需求可追踪到文件和验收项；待确认与未执行内容明确标记。
- **功能开发完成：**G1 通过，代码与配套测试/说明一起交付，默认关闭。
- **功能可上线：**G2、G3 通过；上线后的费用、错误、归组质量观察由指定维护者负责。发生风险先关闭新增流程，已有数据修正用现有工具。

## Key Learnings:

1. SDLC 文档应连接意图、可验证规格、实施计划、评审证据与交接，而不是仅把章节改名。
2. “文档写完”“代码测试通过”“业务验收通过”“生产授权开启”是四个不同状态，不能相互替代。
