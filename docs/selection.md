# 精选与校准

## 一条资料怎么变成精选

1. **收进来**：同一网址、同一内容只留一份。普通文章只有标题或摘要时，按信源规则补取正文；视频播放页使用已提供的文字材料，不把播放器页面当正文。没有可信发布时间的资料先不公开，读到原文日期后再判断新旧（见 [信源](sources.md#规则旧文不刷屏) 的“旧文不刷屏”）。
2. **预筛**（`prefilter.md`）：这是不是本行业的事。宽进，只拦明显无关的：`BLOCK` 的资料不出现在任何公开页面；`PASS` 和拿不准的 `UNKNOWN` 继续往下走。只有标题、没有正文、订阅摘要或帖子文字的普通文章先等待材料，不评分、不凭标题写文案，也不进入公开池；材料补齐产生新修订后再判断。可展示的空文字或纯链接原帖沿用原有评分与原样展示规则。
3. **评分**（`selection-score.md`）：同一份评分标准独立打两次分（0–100）。**两次之和 ≥ 2 × 门槛**就够分，门槛按信源分级不同；够分的还要过第 6 步的去重才进精选。页面上显示的分数是两次的平均（向下取整）。
4. **结构化**（`structure.md`）：和评分同时进行。给出分类和标签（页面上显示的就是这一份）、主体公司，判断这篇是一条具体新闻、讲多件事的综合稿，还是材料不够、说不清；是具体新闻的，抽出它的事实（谁、做了什么、对什么、什么时候）和原文里的出处、前提条件。主题页、事件归组和日报都靠它。
5. **写标题摘要**：等结构化完成再写。入选的和差一点入选的（平均分高于 `understandFloor`），按 `content-understanding.md` 写中文标题、答案先行的摘要和推荐理由；其余的按 `summarize-*.md` 写简短的标题摘要，进“全部动态”。X 帖子没有正文或只含链接时，保留原帖的链接、图片和引用，不调用写作或翻译模型，也不生成“请补充正文”的文案；已经取得实际正文的 X 长文照常处理。
6. **归组与去重**（`group-*.md`）：不同来源报道的同一件事归成一个事件，事件页有综述（`story-digest.md`），“热门”按事件排。修改综述提示词前，可用 [综述评测](story-digest-evaluation.md) 在同一批事件上把现有提示词和候选提示词并排比较。分数够了的资料要等归组完成才进精选：模型同时判断它和精选里已有的报道是不是同一条新闻，以及它有没有精选还没给过的具体信息。
   - 同一条新闻的几篇报道都可以入选：网页上折成一个阅读组；API、RSS 和同步接口每条新闻只出一条，由代表报道出面：官方一手优先；其次是核实过的官方账号（填了 `publisherRole` 和 `owner_entity_id` 的 `T1_5` 账号，新闻的主体正是这家公司，机构先于个人）；再往后是有全文的、分数高的、发得早的。
   - 不是同一条新闻、但没有新信息的（换个说法再介绍一遍已经披露的能力、只是上架到别的平台、只重复已选要点的汇总），不进精选，留在“全部动态”。讲多件事的综合稿不单独成事件，只挂到它提到的事件上，有精选没覆盖的重要内容才入选；材料不够、确认不了是哪条新闻的，不进精选。
   - 确认之前资料只在“全部动态”里，等得再久也不会自动放行。模型调用失败或回答不合格式，这条资料就停在那里：等待超过 10 分钟会告警，后台“运行”页列出这些资料，可以在后台“内容诊断”里打开这条资料，点“重新归组”。所以归组用的模型要能稳定按格式回答。
7. **日报、周报、月报**：
   - **日报**每天 08:00 出（日报、周报、月报的出刊时间在 `site/site.ts` 的 `EDITION_TIMES`，下面按默认值写），覆盖前一天 08:00 到当天 08:00，按规则编排，不调用模型。一件事一条，取报道最多的那条新闻里最权威的一篇，同一事件当天的其他进展列在下面，讲多件事的综合稿挂到它提到的最重要那件事下面。最近 7 期报过的不再出现；报过的事件再有进展，只有当事方自己有新动作（教程、观点这类 `commentary` 类别不算）、或这条进展有 4 家以上信源报道时才进正文，其余进快讯。没有报道入选、但有官方原帖并且已有 3 个以上独立参与方的事件也会补进来（只进日报，不进精选、不推送）。按重要性排序（入选报道的最高分、当天讨论它的独立参与方、有没有官方原帖，跟进的减分），前 12 条进正文，同一信源最多 2 条，再往后最多 10 条一行快讯。第一条是头条，导语就是它自己的标题和摘要；第 2–4 条是今日看点。
   - **周报**（每周一 10:00）和**月报**（每月 1 日 10:30）由这一周、这个月的日报汇编：同一事件跨天只算一件，按日报给它的位置（头条、看点、上了几天）、报道面和评分排序，周报取前 20 件、月报取前 30 件，按日报的分节分栏目。模型（`report-period.md`、`report-period-sections.md`）只写总述和三件以上栏目的一句导读，不增删条目；它写出了条目里没有的名字或数字（拉丁字母的名称、三位以上或带小数点、百分号的数字、词表里的公司），这段话就不用：总述换成按模板生成的一句，栏目不放导读。行业通用词（`taxonomy.ts` 的 `PLAIN_TERMS`）和站名不受这个限制。
   - 每条精选只进一期：按它的时间算，确认入选比它晚的按确认时间；截止以后才确认的进下一期。
   - 每半小时检查一次：到点的刊期出一次，已经出过的不重写；停机错过的、失败的，在之后的检查里补上。窗口里没有可收的条目时这一期不出，之后每半小时再试，到 10 点还没有当天的日报会告警。

每一步的提示词都在 `industry/prompts/`，改提示词不用改代码。提示词的版本就是它内容的哈希：改了提示词，之后的新资料按新版判断，已经判过的不会重算。

## 读者可见的「为何入选」

精选详情会展示只读解释（不是后台诊断）：平均分相对该信源分级门槛、是否过线、信源分级标签；新评分若带回五轴与内容类型也会展示短条。列表卡片只在评分悬停提示里带「分数 · 门槛 · 分级」。事件「为什么热」在通稿近重复合并导致独立参与少于报道数时多一句说明。历史分析没有轴时只降级展示分数与门槛。门槛数字仍只在 `industry/selection.ts`，本能力不改它们。


## 门槛：`industry/selection.ts`

```ts
export const SELECTION = {
  thresholds: { T1: 45, T1_5: 50, T2: 60 },   // 两次评分的平均至少要到这个数（游戏向：官方更低；2026-10-12 收紧）
  understandFloor: 20,                        // 平均分高于它的未入选资料，也按入选的写法写
};
```

官方一手信源（T1）门槛低一些，媒体和个人（T2）门槛高一些：同样一件事，官方原文更值得先看。没有门槛的分级（`EXCLUDE_MP`）不参与精选。

游戏向门槛（2026-10-12）：T1=45 / T1_5=50 / T2=60，相对 10-10 的 30/35/40 收紧，按线上日量把精选压到约十几–三十出头；仍保持 T1 < T1_5 < T2。只影响之后新分析；已入选条目需 `--force-analyze` 重评才会翻选。换评分标准或扩样后仍要按下面的办法重测。

## 校准

门槛数字（`industry/selection.ts`）换行业后要按标注样本重测。**评测脚本只会打印建议，绝不会自动改写门槛文件**；改数字须你本人确认。

### 1. 准备样本集（金标）

从你自己的信源里挑 100–200 条资料，存成 `.data/gold.jsonl`（`.data/` 不进 Git）。每行一条，格式与 `scripts/eval-selection.ts` 的 `GoldRow` 一致：

```json
{"caseId":"gh-001","material":{"title":"原文标题","originalTitle":null,"publishedAt":"2026-10-01T09:00:00+08:00","sourceName":"信源名称","bodyZh":"正文……","bodyOriginal":null,"sourceUrl":"https://…"},"sourceFacts":{"sourceKind":"rss","sourceTier":"T2","firstParty":false,"language":"zh"},"samplingContext":{"benchmarkSplit":"development","samplingStratum":"sts2"},"gold":{"decision":"select","note":"可选标注理由"}}
```

| 字段 | 说明 |
|---|---|
| `caseId` | 唯一编号 |
| `material` | 标题、原标题、发布时间、信源名、正文（`bodyZh` / `bodyOriginal` 有一个即可）；可选 `sourceUrl` 供补正文 |
| `sourceFacts` | 信源类型、分级、是否一手（线上只有 `T1` 算一手）、语言。**分级决定用哪个门槛** |
| `samplingContext` | 可选。`benchmarkSplit`：`development` / `holdout`；`samplingStratum`：分层（见下） |
| `gold.decision` | `select` 应选，`reject` 应排除，`either` 两可（不计入准确率） |

`industry/gold.example.jsonl` 有游戏向示例。

#### 标注口径（灵感 / GAMEHOT）

围绕「会不会改变国内玩家**玩不买、买不买、等不等**」；「一手出处 / 有新信息 / 国内相关」**三者任一**即可应选。种子主题：以撒重生、杀戮尖塔 2、喵喵的结合、博德之门 3。

| 标签 | 何时用 |
|---|---|
| **应选** `select` | 发售日/预购、大版本/DLC、影响玩法的改动、国服相关、版号与监管、有分量的深度等 |
| **应排除** `reject` | 攻略配队、抽卡、软文、无源爆料、搬运、标题党、八卦、折扣史低、账号交易；**小热修 / 只修 bug 的补丁默认应排除** |
| **两可** `either` | 拿不准、或通稿重复信息量难判时（不进 decisive 指标） |

`samplingStratum` 建议用主题 slug（`isaac` / `sts2` / `mewgenics` / `bg3`）或排除类（`guide` / `rumor` / `noise` / `hotfix` / `industry`…）。

几条建议：

- 正式校准必须有**正文**（不要只用标题）。可用 `scripts/gold-enrich-bodies.ts` 按 `sourceUrl` 补取（先 Readability，可选 Jina）。
- 多放**难例**；约 **7:3** 分开发集 / 留出集。
- 评测只跑预筛 + 两次评分（**不跑写作、不含归组去重**）：按本条本身该不该选来标。
- 评测判定用「分数 + 分级门槛」，**不依赖写作步骤**；线上发布仍保留「写完文案才算 relevance=pass」的门闩，二者不同。

补正文示例：

```bash
node --env-file=.env scripts/gold-enrich-bodies.ts --in .data/gold.jsonl --out .data/gold.jsonl
# 或从校准草稿（含 url + draftLabel）生成金标草稿：
node --env-file=.env scripts/gold-enrich-bodies.ts --from-sample /path/to/calibration-sample.json --out .data/gold.jsonl
```

### 2. 跑评测

```bash
# 评测会调模型：临时打开安全阀
MODEL_CALLS_ENABLED=true node --env-file=.env scripts/eval-selection.ts \
  --gold .data/gold.jsonl --split development --label "gamehot-cal-v1"
```

对每条样本跑预筛和两次评分，输出：

- **overall** 准确率、查准率、查全率、F1、入选比例；
- **按信源分级（T1 / T1_5 / T2）** 的同一套指标；
- **门槛扫描**：统一平均分 t 从 40 到 90 每隔 2 分（可用 `DEPLOYMENT.selectionGold.sweep` 改）；并打印**只读建议**（不会写 `industry/selection.ts`）；
- 判错条目；完整报告写入 `.data/eval/`，并导入后台 SelectBench（`--no-import` 可跳过）。SelectBench 运行页可看 by-tier 与扫描表。

不传 `--models` 时，用线上「精选评分」模型（后台切换 > `SCORE_MODEL` > `site/models.ts` > `.env` 的 `LLM_*`）。常用参数：`--n 200`、`--split holdout`、`--no-import`。在 `site/site.ts` 的 `DEPLOYMENT.selectionGold` 写好默认金标路径与扫描范围后，可不带参数运行。

同一次评测里，相同评分输入共享模型结果；各样本仍按自己的预筛、分级门槛和标注计分。重复运行会复用回执。

### 3. 看错例，改标准，再跑

在后台 SelectBench 里逐条看 FP/FN：

- 该选没选上 → 多半是 `selection-score.md` 没写清价值；
- 不该选却选上 → 噪声上限不够；
- 整体松紧、分数贴门槛 → **你确认后**再改 `industry/selection.ts`（先改标准，再动门槛）。

先改标准，再动门槛。每改一次跑一遍；拍板前用留出集确认。**禁止**让脚本或 CI 自动写回门槛文件。

## 换模型

后台“模型与评测”页能看到每一步当前用哪个模型、近期的成功率、耗时和 token 用量，也能直接切换（只影响之后的新任务）。换评分模型之前，先用 `--models` 在同一批样本上比一比。
